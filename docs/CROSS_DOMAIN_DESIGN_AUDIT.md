# Cross-domain design, frontend, SEO and analytics audit

**ID:** AUDIT-DESIGN-01 · **Version:** 0.1 · **Status:** historical bounded review; current dispositions below · **Owner:** Documentation architect · **Reviewers:** UX, frontend, SEO, analytics, backend, security · **Updated:** 2026-11-15

## Scope and method
Compared the proposed UX screen inventory and wireframes (05), tokens and components (06), motion (07), frontend architecture and routes (11), SEO strategy/URLs/indexation (16), and analytics events/KPIs (17), plus the domain envelope in 10/08. This is a document consistency check, not a usability study, technical implementation test, WCAG conformance assessment or stakeholder sign-off. It does not establish that the overall package is implementation-ready.

## Test-oriented remediation checklist
- Run route contract tests for anonymous, pending dealer, approved bidder, seller owner, branch staff and unauthorized staff. Verify public markup/canonical/sitemap and absence of private auction data.
- Run analytics contract tests for duplicate event IDs, consent denied, late delivery, projection mapping and settlement verification/reconciliation distinction; compare aggregate results to operational sources.
- Prototype SCR-003, 005, 008, 017, 022 and 026 at required breakpoints and zoom; test keyboard, screen reader, focus visibility, countdown announcements and reduced motion.
- Produce a complete screen/role/API/event/test mapping; define analytics retention, small-cohort threshold, attribution window, and legal basis with owners.
- Validate all theme colors and component states, actual assets, network budgets and field p75 measures; record failures, owners and retests.

Until these checks and the program's P0 commercial, legal and auction decisions are complete, this audit is an issue list, not a release or implementation-readiness approval.
